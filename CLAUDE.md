# CLAUDE.md — personal_website

Workspace rules: ../CLAUDE.md (env, ports, git, privacy).

## What this is

Static personal site on GitHub Pages: plain HTML + CSS + vanilla JS, no framework, bundler,
CDN or trackers; `.nojekyll` serves files as-is. Generated by `build.py` (stdlib-only, any
Python ≥ 3.11) from `src/`; the HTML is written to the repo root and **committed**, so Pages
needs no CI. `README.md` is the authoring guide — read it before editing content.

Not a Python app: no `core/`, `storage/` or pytest suite. Verification is `build.py --check`.

## Commands

```
PY=~/miniconda3/envs/investing/bin/python
$PY build.py --check    # build + every gate; run before committing
$PY build.py --serve    # build, then http://localhost:8910
# Playwright tools need the conda env's libnss3:
export LD_LIBRARY_PATH=$HOME/miniconda3/envs/investing/lib
$PY tools/audit.py                        # browser checks --check cannot do; exits non-zero on failure
$PY tools/shots.py --out /tmp/shots/after # screenshot matrix (--out is required)
```

## Architecture

- `build.py` — TOML frontmatter, `{{token}}` substitution, includes, blog index, RSS,
  prev/next, and the `--check` gates. Sources: `src/site.toml`, `src/templates/`,
  `src/partials/` (incl. `diagrams/*.svg`), `src/pages/`, `src/blog.html`, `src/posts/`
  (`_TEMPLATE.html` is skipped). Styles `css/styles.css`, behaviour `js/main.js`.
- **Never hand-edit a generated file at the repo root** (`index.html`, `projects.html`,
  `blog.html`, `404.html`, `feed.xml`, `posts/*.html`) — the next build overwrites it.

## Conventions

- **Templating is deliberately primitive** — `{{ key }}` and `{{ include:path }}`, no
  expressions or loops; anything list-shaped is assembled in `build.py`, so the generator
  stays one readable file.
- **`--check` is the test suite** — tokens, links, frontmatter, feed, social card, WCAG AA
  contrast in both themes, diagram label size, reveal gating, control size and more, all
  arithmetic over the sources. Add a gate rather than relying on a manual look.
- **`tools/audit.py` is the other half** — rendered contrast, label sizes, clipping, tap
  targets, print colours, survival without `main.js`. Run it before a visual commit.
- **`build.py` stays dependency-free** — anything needing a package (the social-card
  renderer `tools/make_og.py`) lives in `tools/`, is run by hand, and its output committed.
- **JS is enhancement only, enforced** — `.reveal` is hidden under `.reveal-on`, which
  `main.js` sets as its first action; gating on the inline head script's class blanked the
  page when `main.js` failed. `--check` fails if the two drift. Never add content that
  appears only after script runs.
- **Diagrams** go in `src/partials/diagrams/` as inline SVG with the shared `d-*` classes,
  wrapped in `.diagram > .diagram__scroll`; `.diagram svg` has a `min-width` so narrow
  screens scroll rather than shrink. Size type in the CSS `d-*` classes, not in the
  drawings — growing type in the fixed 900-unit space pushes labels through their boxes.
- **Playwright tools need** `channel="chromium"` (the default headless shell is a different
  binary) and `LD_LIBRARY_PATH=$HOME/miniconda3/envs/investing/lib` (`libnss3` lives in the
  conda env). Capture before and after a visual change; still check motion and focus order
  in a real browser.

## Privacy — read this before adding anything

**The one repo whose content is published deliberately.** It puts the owner's name,
biography, contact address and CV under their own domain, so `.privacy-guard-allow`
disables `denylist-name` and `contact` here and exempts `assets/**` from scanning.

That exemption is the reason to be careful, not a reason to relax:

- **Anything under `assets/` is world-readable and unscanned** — check every file added
  there, especially a new CV revision, for a phone number, home address or anything else
  that should not be public.
- **Every other rule still applies** — no account or card numbers, no real financial
  figures, no third-party names (they have not consented to being published).
- The site **describes** the other projects at the owner's request: architecture,
  engineering metrics and lessons only. No repo links (those repos are private), no
  screenshots of real dashboards, no holdings, tickers, amounts, or bank/broker names.
- A post about a bug is fine; pasting the data that revealed it is not. Use a measurement
  or an explicitly synthetic number.
- An example card or account number in prose is correctly blocked by the guard — describe
  formats rather than instantiating them.

## Known limitations

- Generated root files are committed, so diffs are larger than the edit — the price of no CI.
- No syntax highlighting; code blocks are escaped by hand.
- Posts are HTML fragments, not Markdown — diagrams and callouts are inline HTML anyway.
- Repo visibility governs whether Pages serves it; confirm before assuming a push goes live.
