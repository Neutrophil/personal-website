# Junjie Chen — Personal Website

A fast, dependency-free personal site showcasing my work in clinical genomics, bioinformatics
and machine learning, built to support a job search toward **AI for Life Science**.

- **Live URL (once deployed):** https://neutrophil.github.io/
- **Stack:** plain HTML + CSS + vanilla JS, generated by a stdlib-only Python script.
  No Node, no framework, no bundler, no CDN, no trackers.

## Structure

Sources live in `src/`. Generated HTML is written to the repo root **and committed**, so
GitHub Pages keeps serving plain files with no CI step.

```
build.py                     # the generator — stdlib only, ~330 lines
src/
  site.toml                  # site metadata + primary nav
  templates/base.html        # the one page skeleton (head, theme script, chrome)
  templates/post.html        # article wrapper for a post body
  partials/nav.html          # header chrome
  partials/footer.html
  partials/signal.svg        # hero waveform
  partials/diagrams/*.svg    # six theme-aware inline diagrams
  pages/index.html           # body fragment + TOML frontmatter
  pages/projects.html
  pages/404.html
  blog.html                  # the writing index (post list is generated into it)
  posts/*.html               # one fragment per post, + _TEMPLATE.html

css/styles.css               # design system: dark default + light counterpart
js/main.js                   # theme toggle, nav, reveal, tag filter, copy buttons, progress
tools/make_og.py             # regenerates assets/og.png (Pillow + fontTools; by hand)
tools/shots.py               # screenshot matrix for a visual diff (Playwright; by hand)
tools/audit.py               # browser-side checks --check cannot do (Playwright; by hand)
assets/fonts/                # JetBrains Mono, subset to this site (OFL, ~75 KB, 3 weights)
assets/cv/                   # downloadable CV (PDF)
assets/favicon.svg
assets/og.png                # 1200x630 social card, committed
.nojekyll                    # serve files as-is on GitHub Pages

index.html projects.html blog.html 404.html feed.xml posts/*.html   # ← generated, committed
```

## Build and preview

```bash
cd /home/junjie/claude/personal_website
~/miniconda3/envs/investing/bin/python build.py --check     # build + run every gate
~/miniconda3/envs/investing/bin/python build.py --serve     # build, then http://localhost:8910
```

`--check` is not decoration. It fails the build on:

- an unresolved `{{ token }}` anywhere in the output;
- a local `href`/`src` that does not resolve to a file on disk (this catches the broken
  relative paths the two-directory layout invites);
- a post missing `title`, `date`, `summary` or `tags`, or with a uselessly short summary;
- `feed.xml` not parsing, or containing a relative link;
- a missing `assets/og.png` — every page references it by absolute URL, which the link
  checker cannot follow, so it is checked separately;
- **any text/background pair falling below WCAG AA contrast, in either theme** — the ratios
  are computed from the tokens in `css/styles.css`, so changing a colour tells you immediately;
- a diagram whose smallest label would render below 10px once the figure is scaled to fit;
- a `.reveal` gating class that `js/main.js` does not actually set — the check that stops a
  failed script from blanking the page;
- a control declared smaller than 24px, more than one current-page marker on a page, or a
  page with no `theme-color`.

Run it before every commit.

## The browser-side checks

`--check` reasons about the sources and has no browser, so it cannot see a colour after alpha
compositing, a label inside a scaled SVG, or what happens when a script fails. `tools/audit.py`
does, and exits non-zero the same way:

```bash
export LD_LIBRARY_PATH=$HOME/miniconda3/envs/investing/lib
~/miniconda3/envs/investing/bin/python tools/audit.py     # contrast, targets, print, no-JS
~/miniconda3/envs/investing/bin/python tools/shots.py --out /tmp/shots/after
```

`shots.py` writes six pages x two themes x two widths, plus strips sliced to viewport height,
which is what makes a before-and-after diff readable.

## The social card

`assets/og.png` is what Slack, LinkedIn and the rest show when someone pastes a link. It is
generated by `tools/make_og.py` and **committed** — the script is not part of `build.py`
because it needs Pillow, and the point of the generator is that it needs nothing.

```bash
~/miniconda3/envs/investing/bin/python tools/make_og.py
```

Re-run it by hand if the wordmark or the palette changes. It draws from the same colours as
`css/styles.css`, but nothing enforces that — keep them in step yourself.

## Publishing a blog post

Three steps, only one of which is writing:

1. Copy `src/posts/_TEMPLATE.html` to `src/posts/YYYY-MM-DD-slug.html`.
2. Fill in the TOML frontmatter (`title`, `date`, `summary`, `tags`) and write the body as an
   HTML fragment — no `<html>`, no nav, no footer. The template shows every available
   component: code blocks with a filename bar, callouts, diagram figures, data tables.
3. `python build.py --check`, then commit.

The blog index, tag filter, RSS feed, prev/next links and reading time are all derived from
the frontmatter. There is no list to maintain by hand.

To add a diagram, drop an SVG into `src/partials/diagrams/` and include it with
`{{ include:diagrams/name.svg }}`. Use the shared `d-*` classes (`d-label`, `d-accent`,
`d-fill-elev`, …) so it follows the theme and matches the others.

## Design system

The display and UI face is **JetBrains Mono**, self-hosted from `assets/fonts/` and subset to
the glyphs this site actually renders — 274 KB of upstream woff2 becomes 75 KB across three
weights. It is licensed under the OFL, whose text sits beside the files. Body copy stays on the
system sans stack. Re-run the subsetting if the copy gains glyphs it does not cover.

Dark is the default; light is a deliberate counterpart, not an inversion. Both are defined as
custom properties at the top of `css/styles.css` — `:root` for dark, `[data-theme="light"]`
for the overrides. An inline script in `<head>` resolves the theme before first paint and
swaps `no-js` for `js` on `<html>`, which is what lets scroll-reveal degrade to plain visible
content when scripting is unavailable.

Everything in `js/main.js` is an enhancement. If it fails to load the site is still complete.

## Deploy to GitHub Pages

This is a **user site**, so the repo must be named exactly `neutrophil.github.io`.

1. Rename the repo to `neutrophil.github.io` and make it public (a deliberate decision — see
   `CLAUDE.md`; every other repo in this workspace stays private).
2. Settings → Pages → source: `main` branch, `/root`.
3. Push. Stage explicit paths — never `git add -A`, per the workspace rule.

```bash
~/miniconda3/envs/investing/bin/python build.py --check
/home/junjie/claude/tools/privacy-guard scan .
git add index.html projects.html blog.html 404.html feed.xml posts/ src/ css/ js/ build.py
git commit -m "..."
git push
```

A custom domain can be added later under Settings → Pages → Custom domain.
